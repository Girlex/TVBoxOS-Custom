修复思路

保留你要的单一自建融合源与 1400 个站点完全不动（不丢内容、不去重结果不变、全部走本地），只从运行时代码侧消除崩溃与阻塞。诊断依据见 tools/tvbox_freeze_analysis.html。

#问题修复代码位置
1ART 并发类校验竞态 → StatusVerifying native abort，进程被杀新增 DEX_CLASS_LOCK 静态全局锁，new DexClassLoader、核心类预热、loadClass/newInstance、解析器类与 Proxy 注入全部串行化；只锁微秒级类加载动作，绝不含联网逻辑JarLoader.java
2一次搜索遍历 1400 站点，ANR / 长时间转圈按融合源的测速顺序只取前 120 个站点；并发 6→3（上限 12→4）、单站点超时 15→8 秒FastSearchActivity.java
3jar 的 Init.init() 同步联网拉 so（12 次 404）阻塞 7.5 秒改为 FutureTask 最多等 3 秒，超时后台线程继续跑完、调用方立即前进；后台执行抛异常时回退调用线程重试保证兼容；加密 jar 绑定保持同步原语义JarLoader.java
4校验脚本把「签名不一致」误报原实现哈希整个 META-INF/CERT.RSA，其中含 signingTime，同一密钥每次构建都不同。改为用 openssl 从 PKCS#7 取 X.509 证书 DER 算 SHA256，并以仓库 TVBoxOSC.jks 为权威基准；--record 改为校验全通过才写基线check_apk_installability.py
