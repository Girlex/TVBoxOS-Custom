怎么用

  • 同一局域网（最快）：在电脑上跑 python3 tools/make_my_api.py --serve 8000， 窗口里会打印形如 http://192.168.x.x:8000/personal.json 的地址，把它填进电视的配置地址即可。 注意 TVBox 的 configUrl() 会给非 http 地址强行补 http://， 所以不能直接填 /sdcard/personal.json 这类本地路径。
  • 长期使用：把 personal.json 上传到任意能直连的静态托管（GitHub raw / Gitee / 自己的 HTTP 目录）， 配置地址填该 URL；加 --public-base <该目录前缀> 重跑还会生成 collection.json。
  • 内置进 APK：把 personal.json 放到 app/src/main/assets/builtin/configs/， 配置地址填 clan://localhost/builtin/configs/personal.json，重编译后离线可用。
  • 只想要单个接口：kept_urls.txt 第一行就是实测最快的原始接口地址。
  • 定期复测：重跑脚本会覆盖输出；把新地址追加进 tools/my_api/urls.txt 一起过筛， 重复的会自动合并，老地址失效的会被自动剔除。

判定口径

  • 去重：接口层按「解析后真实地址 + 配置内容 md5」判重，重复保留响应更快的那份；站点层按 key 与 (name, api) 双重判重，同名同地址只留最快接口的版本。共用同一个 spider jar 不算重复。
  • 卡不卡：只看可测的网络层指标（TTFB、jar 下载），不猜站点内容质量。等级：优 ≤1.0s、良 ≤2.5s、 可用·偏慢 ≤5.0s、超过阈值剔除。
  • 站点存活：按 api 的域名聚合探测，连不上（DNS 失败 / 拒绝 / 超时）才剔除； 返回 403/404 仍保留——很多站点接口对裸请求就是这个反应，不代表不能用。
  • jar 绑定：融合后每个站点显式写自己的 jar（绝对地址），避免不同来源的站点互相串用爬虫。
  • 只验证「配置能不能拿到 / 爬虫能不能下 / 域名通不通」，不验证版权与内容合规，也不替代设备端实际播放测试。
