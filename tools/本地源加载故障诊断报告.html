本地源「加载不出来 / 搜索对不上」诊断与修复

设备 ZTE S2002（Android 7.1 / API 25）· 抓日志时间 2026-11-18 19:26 · 修复版本 v1008

一、现象 你反馈的问题

  • 装上内置本地源的 APK 后，长时间卡在启动转圈，进不了主界面。
  • 勉强进去后，站点列表能看到名字，但「搜索的内容和显示的不同，找不到我要的」。

二、抓日志定位到的根因 logcat 实锤

冷启动抓 logcat（tools/device_logs/tvbox_app_log.txt）发现两条致命错误：

ClassNotFoundException: Didn't find class "com.github.catvod.spider.http://127.0.0.1:9978/file/builtin/scripts/813ab0b864s.txt" No original dex files found for dex location .../cache/jar/d7e3517dc9cff9c72c989b881dfc2d61.jar
#根因后果
182 个脚本文件名后缀全是 .txt。而客户端按 api 后缀分流（.js→JS加载器 / .py→Python / 其余→jar加载器），.txt 被误当成 Java 类名去加载脚本类站点全部加载失败 —— 这就是「显示有、搜不到」的直接原因：近一半站点是点开就报错的假站点
23 个 jar 损坏（开头虽是 PK 但 zip 中央目录坏，读不出 classes.dex），却被打包了进去No original dex，依赖它们的站点同样加载失败
3编译的是 java 版 APK，不含 Python 环境，却有 25 个 Python 爬虫站点日志 Python is not supported，这 25 站永远搜不出结果

附：首次冷启动那次转圈是系统在后台做 dex2oat 首次编译（190 个 spider 类，约 1~2 分钟），属于老设备正常开销，不是崩溃。

三、为什么会出现 流程疏漏

生成脚本 build_local_good.py 里「保留 .js/.py 后缀」的逻辑其实早就改对了，但上一次重跑时被环境的中途中断拦在写文件之前，assets 里一直是旧版全 .txt 的产物。也就是说：代码修了，但从没真正完整重跑生成过 —— 打包进去的还是坏数据。

四、修复措施 已完成

1

脚本后缀强制跟随真实类型：统一用 script_ext_of()，本地脚本保留 .js/.py/.json，绝不写成 .txt。

2

jar 加强校验：valid_jar() 用 zipfile 实际读出 classes.dex，假 jar 自动删缓存重下，仍坏则剔除（连带剔除依赖它的 12 个站点）。

3

剔除 25 个 Python 站点：java 版 APK 不支持；ext 里被 drpy.js 引擎调用的 .py 不受影响，保留。

4

清理无引用残留：脚本目录 114 个旧文件清掉，assets 从 105 个文件瘦身到 66 个。

5

重新生成 + 云编译 + 覆盖安装：commit a325e8f，run #44296957357 成功，APK v1008。

七、给你的建议

  • 把当前 APK（apk/TVBox_debug-java.apk，v1008）装到电视，首次开机耐心等 1~2 分钟让它把爬虫编译好。
  • 之后搜索就能正常出结果了——之前「搜不到」的那些站点已经从源头剔除，不再占位。
  • 以后站点有更新：重跑 python3 tools/build_local_good.py（完整跑，别中断），再云编译即可。
